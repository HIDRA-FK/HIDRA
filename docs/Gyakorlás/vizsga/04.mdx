# 4. feladat – Karbantartási bejelentések adatainak vizsgálata

Egy középiskola belső karbantartási bejelentő rendszert használ az épületben és a tantermekben jelentkező problémák nyilvántartására. A dolgozók bejelentést adhatnak le például világítási hiba, fűtési probléma, bútorhiba vagy teremtechnikai probléma esetén.

A feladatot a vizsgán biztosított MySQL adatbázis-szerveren kell elvégeznie.

A feladat megoldásának megkezdése előtt futtassa le az `elokeszites.sql` nevű előkészítő scriptet! A script létrehozza a `JuniorKarbantartasDB` adatbázist, a `Bejelentesek` táblát, valamint feltölti azt a szükséges adatokkal.

A lekérdezéseket az előkészített `JuniorKarbantartasDB` adatbázison készítse el!

Az adatbázisban a `Bejelentesek` tábla áll rendelkezésre.

| Mező neve | Típus | Tartalma |
|---|---|---|
| `Id` | Egész szám | A bejelentés egyedi azonosítója |
| `BejelentoNev` | Szöveg | A bejelentést leadó dolgozó neve |
| `Helyszin` | Szöveg | Az a helyszín, ahonnan a bejelentést leadták |
| `Kategoria` | Szöveg | A bejelentett probléma típusa vagy témaköre |
| `Prioritas` | Szöveg | A bejelentés sürgőssége, például `Alacsony`, `Közepes` vagy `Magas` |
| `Allapot` | Szöveg | A bejelentés aktuális feldolgozási állapota, például `Nyitott`, `Folyamatban` vagy `Lezárt` |
| `LetrehozasDatuma` | Dátum | A bejelentés létrehozásának dátuma |

A megoldásokat `karbantartas.sql` néven készítse el!

## Feladatok

1. Kérdezze le az összes bejelentés minden adatát!

2. Kérdezze le azokat a bejelentéseket, amelyek állapota `Nyitott`!

3. Kérdezze le a `Magas` prioritású bejelentések bejelentőjét, kategóriáját és létrehozási dátumát!

4. Kérdezze le azokat a bejelentéseket, amelyeket az `Informatika terem` helyszínről adtak le!

5. Határozza meg, hogy kategóriánként hány bejelentés szerepel a rendszerben!

6. Határozza meg, hogy helyszínenként hány nyitott bejelentés van!

7. Kérdezze le a nyitott bejelentéseket létrehozási dátum szerint növekvő sorrendben, hogy a legrégebbi megoldatlan ügyek jelenjenek meg elöl!

## A feladat célja

A feladat célja egy karbantartási bejelentéseket tartalmazó adatbázis lekérdezése MySQL utasításokkal.

Az adatokat a `JuniorKarbantartasDB` nevű adatbázis tartalmazza.

Az adatbázison belül a `Bejelentesek` nevű tábla áll rendelkezésre.

A tábla minden sora egy karbantartási bejelentést jelöl. A sorokban megtalálható többek között:

- a bejelentés azonosítója,
- a bejelentő dolgozó neve,
- a helyszín,
- a probléma kategóriája,
- a prioritás,
- az állapot,
- a létrehozás dátuma.

## Az előkészítő SQL script szerepe

Az `elokeszites.sql` script azért szükséges, mert ez hozza létre a feladat megoldásához szükséges adatbázist és táblát.

A lekérdezések csak akkor működnek megfelelően, ha az előkészítő script korábban már lefutott.

## Az adatbázis törlése, ha már létezik

```sql
DROP DATABASE IF EXISTS JuniorKarbantartasDB;
```

Ez az utasítás törli a `JuniorKarbantartasDB` adatbázist, ha az már létezik.

```sql
DROP DATABASE
```

A `DROP DATABASE` adatbázis törlésére szolgál.

Ha egy adatbázist törlünk, akkor az adatbázisban található táblák és adatok is törlődnek.

---

### Az IF EXISTS szerepe

```sql
IF EXISTS
```

Az `IF EXISTS` azt jelenti, hogy a törlés csak akkor történjen meg, ha az adatbázis valóban létezik.

Ez azért hasznos, mert ha az adatbázis még nem létezik, a parancs nem okoz hibát.

## Az adatbázis létrehozása

```sql
CREATE DATABASE JuniorKarbantartasDB
CHARACTER SET utf8mb4
COLLATE utf8mb4_hungarian_ci;
```

A `CREATE DATABASE` új adatbázist hoz létre.

Ebben az esetben az adatbázis neve:

```text
JuniorKarbantartasDB
```

---

### A CHARACTER SET szerepe

```sql
CHARACTER SET utf8mb4
```

A `CHARACTER SET` karakterkódolást állít be.

Az `utf8mb4` olyan karakterkódolás, amely alkalmas magyar ékezetes karakterek tárolására is.

Ez azért fontos, mert a feladatban sok magyar szöveg szerepel, például:

```text
Kovács Anna
Fűtési probléma
Világítási hiba
Áramellátási probléma
```

---

### A COLLATE szerepe

```sql
COLLATE utf8mb4_hungarian_ci
```

A `COLLATE` az összehasonlítási és rendezési szabályokat határozza meg.

Az `utf8mb4_hungarian_ci` magyar nyelvhez illeszkedő rendezési szabályokat használ.

A `ci` jelentése case-insensitive, vagyis kis- és nagybetűket nem különböztet meg az összehasonlításnál.


A `PRIMARY KEY` elsődleges kulcsot jelent.

Ez azt jelenti, hogy az `Id` mező értéke egyedileg azonosítja a sorokat. Két különböző bejelentés nem kaphatja ugyanazt az `Id` értéket.

---

### A BejelentoNev mező

```sql
BejelentoNev VARCHAR(100)
```

A `BejelentoNev` mező a bejelentést leadó dolgozó nevét tárolja.

A `VARCHAR(100)` változó hosszúságú szöveget jelent, legfeljebb 100 karakter hosszúságban.

### A Helyszin mező

```sql
Helyszin VARCHAR(50)
```

A `Helyszin` mező azt tárolja, hogy honnan adták le a bejelentést.

```text
Tanári szoba

Könyvtár
Aula
```

A `VARCHAR(50)` legfeljebb 50 karakter hosszú szöveget enged.

---

### A Kategoria mező

```sql
Kategoria VARCHAR(50)
```

A `Kategoria` mező a bejelentett probléma típusát tárolja.

Példák:

```text
Világítási hiba

Bútorhiba
Teremtechnikai probléma
```

---

### A Prioritas mező

```sql
Prioritas VARCHAR(20)
```

Példák:

```text
Alacsony
Közepes
Magas
```

---

### Az Allapot mező

```sql
Allapot VARCHAR(20)
```

Az `Allapot` mező azt mutatja meg, hogy a bejelentés milyen feldolgozási állapotban van.

Példák:

```text
Lezárt
```

### A csillag szerepe

### A FROM szerepe

A `FROM` azt adja meg, hogy melyik táblából kérdezzük le az adatokat.

## 5. lekérdezés – Bejelentések száma kategóriánként

```sql
SELECT 
    Kategoria,
    COUNT(*) AS BejelentesekSzama
FROM Bejelentesek
GROUP BY Kategoria
ORDER BY Kategoria;
```

Ez a lekérdezés megszámolja, hogy az egyes kategóriákhoz hány bejelentés tartozik.

---

### A COUNT függvény

```sql
COUNT(*)
```

A `COUNT` összesítő függvény.

A `COUNT(*)` megszámolja, hány sor tartozik az adott csoportba.

Ebben a feladatban azt számolja meg, hogy egy-egy kategóriához hány bejelentés tartozik.

---

### Az AS szerepe

```sql
AS BejelentesekSzama
```

Az `AS` alias, vagyis ideiglenes oszlopnév megadására szolgál.

A `COUNT(*)` eredménye így nem névtelen vagy nehezen olvasható oszlopként jelenik meg, hanem `BejelentesekSzama` néven.

---

### A GROUP BY szerepe

```sql
GROUP BY Kategoria
```

A `GROUP BY` csoportosítja a sorokat.

Ebben az esetben a csoportosítás a `Kategoria` mező alapján történik.

Ez azt jelenti, hogy az azonos kategóriához tartozó sorokat egy csoportként kezeli a lekérdezés.

Például minden `Világítási hiba` kategóriájú sor egy csoportba kerül, és a `COUNT(*)` megszámolja, hány ilyen sor van.

---

### Az ORDER BY szerepe

```sql
ORDER BY Kategoria
```

Az `ORDER BY` az eredmény rendezésére szolgál.

Ebben a lekérdezésben a kategóriák neve szerint rendezve jelennek meg az eredmények.

Ez a lekérdezés teljesíti az 5. feladatrészt.

## 6. lekérdezés – Nyitott bejelentések száma helyszínenként

```sql
SELECT 
    Helyszin,
    COUNT(*) AS NyitottBejelentesekSzama
FROM Bejelentesek
WHERE Allapot = 'Nyitott'
GROUP BY Helyszin
ORDER BY Helyszin;
```

Ez a lekérdezés azt határozza meg, hogy helyszínenként hány nyitott bejelentés van.

---

### A WHERE és GROUP BY együttes használata

```sql
WHERE Allapot = 'Nyitott'
GROUP BY Helyszin
```

Ebben a lekérdezésben először a `WHERE` feltétel szűri a sorokat.

Csak azok a sorok maradnak meg, ahol:

```text
Allapot = Nyitott
```

Ezután a megmaradt nyitott bejelentéseket a `GROUP BY Helyszin` csoportosítja helyszín szerint.

---

### Miért fontos a sorrend?

A lekérdezés logikája:

1. a `FROM Bejelentesek` megadja a táblát,
2. a `WHERE Allapot = 'Nyitott'` kiszűri a nyitott bejelentéseket,
3. a `GROUP BY Helyszin` helyszínenként csoportosít,
4. a `COUNT(*)` megszámolja a csoportok elemeit,
5. az `AS NyitottBejelentesekSzama` elnevezi a darabszám oszlopát,
6. az `ORDER BY Helyszin` rendezi az eredményt helyszín szerint.

Ez azért fontos, mert a feladat nem az összes bejelentést kéri helyszínenként, hanem csak a nyitott állapotú bejelentéseket.

Ez a lekérdezés teljesíti a 6. feladatrészt.

## 7. lekérdezés – Nyitott bejelentések rendezése létrehozási dátum szerint

```sql
SELECT 
    *
FROM Bejelentesek
WHERE Allapot = 'Nyitott'
ORDER BY LetrehozasDatuma ASC;
```

Ez a lekérdezés a nyitott bejelentéseket jeleníti meg létrehozási dátum szerint növekvő sorrendben.

---

### A nyitott bejelentések szűrése

```sql
WHERE Allapot = 'Nyitott'
```

Ez a feltétel csak a nyitott bejelentéseket hagyja meg.

A lezárt vagy folyamatban lévő bejelentések nem kerülnek bele az eredménybe.

---

### Az ORDER BY szerepe

```sql
ORDER BY LetrehozasDatuma ASC
```

Az `ORDER BY` az eredmény rendezésére szolgál.

Ebben az esetben a `LetrehozasDatuma` mező alapján rendezzük az eredményt.

---

### Az ASC szerepe

```sql
ASC
```

Az `ASC` növekvő sorrendet jelent.

Dátumok esetében ez azt jelenti, hogy a legkorábbi dátum jelenik meg elöl, majd utána következnek az egyre későbbi dátumok.

Ez azért felel meg a feladatnak, mert így a legrégebbi megoldatlan ügyek jelennek meg elöl.

Ez a lekérdezés teljesíti a 7. feladatrészt.
