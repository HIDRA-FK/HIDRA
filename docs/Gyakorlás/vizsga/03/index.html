3. feladat – Szoftverlicenc-nyilvántartás lekérdezése

Az intézmény informatikai részlege adatbázisban tartja nyilván a használatban lévő szoftverlicenceket. A nyilvántartásban többek között irodai programcsomagok, fejlesztői környezetek, vírusvédelmi szoftverek és grafikai programok adatai szerepelnek.

A feladatot a vizsgán biztosított MySQL adatbázis-szerveren kell elvégeznie.

A feladat megoldásának megkezdése előtt futtassa le az elokeszites.sql nevű előkészítő scriptet! A script létrehozza a JuniorLicencDB adatbázist, a Licencek táblát, valamint feltölti azt a szükséges adatokkal.

A lekérdezéseket az előkészített JuniorLicencDB adatbázison készítse el!

Az adatbázisban a Licencek tábla áll rendelkezésre.

A megoldásokat licencnyilvantartas.sql néven készítse el!

Feladatok​

  1. Kérdezze le az összes szoftver nevét, típusát, helyiségét és beszerzési évét!

  2. Kérdezze le azoknak a licenceknek minden adatát, amelyek jelenleg aktívak!

  3. Kérdezze le a Fejlesztői környezet típusú szoftverek nevét és helyiségét!

  4. Kérdezze le azokat a licenceket, amelyeket 2020 előtt szereztek be!

  5. Határozza meg, hogy helyiségenként hány licenc található az adatbázisban!

  6. Határozza meg, hogy típusonként hány aktív licenc van használatban!

  7. Kérdezze le azokat a licenceket, amelyek utolsó ellenőrzése 2026. január 1. előtt történt! Az eredmény az ellenőrzés dátuma szerint növekvő sorrendben jelenjen meg!

A feladat megoldása előtt létre kell hozni és le kell futtatni az elokeszites.sql nevű fájlt.

Ez az állomány létrehozza a JuniorLicencDB adatbázist, a Licencek táblát, majd feltölti azt a feladat megoldásához szükséges adatokkal.

Az előkészítő script lefuttatása után kell elkészíteni a licencnyilvantartas.sql állományt.

Teljes megoldás
USE JuniorLicencDB;

-- 1. Az összes szoftver nevének, típusának, helyiségének és beszerzési évének lekérdezése
SELECT 
    Nev,
    Tipus,
    Helyiseg,
    BeszerzesEve
FROM Licencek;

-- 2. Az aktív licencek minden adatának lekérdezése
SELECT 
    *
FROM Licencek
WHERE Aktiv = 1;

-- 3. A Fejlesztői környezet típusú szoftverek nevének és helyiségének lekérdezése
SELECT 
    Nev,
    Helyiseg
FROM Licencek
WHERE Tipus = 'Fejlesztői környezet';

-- 4. A 2020 előtt beszerzett licencek lekérdezése
SELECT 
    *
FROM Licencek
WHERE BeszerzesEve < 2020;

-- 5. Licencek számának meghatározása helyiségenként
SELECT 
    Helyiseg,
    COUNT(*) AS LicencekSzama
FROM Licencek
GROUP BY Helyiseg
ORDER BY Helyiseg;

-- 6. Aktív licencek számának meghatározása típusonként
SELECT 
    Tipus,
    COUNT(*) AS AktivLicencekSzama
FROM Licencek
WHERE Aktiv = 1
GROUP BY Tipus
ORDER BY Tipus;

-- 7. A 2026. január 1. előtt ellenőrzött licencek lekérdezése
SELECT 
    *
FROM Licencek
WHERE UtolsoEllenorzes < '2026-01-01'
ORDER BY UtolsoEllenorzes ASC;

<

5. lekérdezés – Licencek száma helyiségenként​

SELECT 
    Helyiseg,
    COUNT(*) AS LicencekSzama
FROM Licencek
GROUP BY Helyiseg
ORDER BY Helyiseg;

Ez a lekérdezés megszámolja, hogy az egyes helyiségekhez hány licenc tartozik.

A COUNT függvény​

COUNT(*)

A COUNT összesítő függvény.

A COUNT(*) megszámolja, hány sor tartozik az adott csoportba.

Ebben a feladatban azt számolja meg, hogy egy-egy helyiséghez hány licenc tartozik.

Az AS szerepe​

AS LicencekSzama

Az AS alias, vagyis ideiglenes oszlopnév megadására szolgál.

A COUNT(*) eredménye így nem névtelen vagy nehezen olvasható oszlopként jelenik meg, hanem LicencekSzama néven.

A GROUP BY szerepe​

GROUP BY Helyiseg

A GROUP BY csoportosítja a sorokat.

Ebben az esetben a csoportosítás a Helyiseg mező alapján történik.

Ez azt jelenti, hogy az azonos helyiséghez tartozó sorokat egy csoportként kezeli a lekérdezés.

Például minden Média labor helyiséghez tartozó sor egy csoportba kerül, és a COUNT(*) megszámolja, hány ilyen sor van.

Az ORDER BY szerepe​

ORDER BY Helyiseg

Az ORDER BY az eredmény rendezésére szolgál.

Ebben a lekérdezésben a helyiségek neve szerint rendezve jelennek meg az eredmények.

Ez a lekérdezés teljesíti az 5. feladatrészt.

6. lekérdezés – Aktív licencek száma típusonként​

SELECT 
    Tipus,
    COUNT(*) AS AktivLicencekSzama
FROM Licencek
WHERE Aktiv = 1
GROUP BY Tipus
ORDER BY Tipus;

Ez a lekérdezés azt határozza meg, hogy típusonként hány aktív licenc van használatban.

A WHERE és GROUP BY együttes használata​

WHERE Aktiv = 1
GROUP BY Tipus

Ebben a lekérdezésben először a WHERE feltétel szűri a sorokat.

Csak azok a sorok maradnak meg, ahol:

Aktiv = 1

Ezután a megmaradt aktív licenceket a GROUP BY Tipus csoportosítja típus szerint.

Miért fontos a sorrend?​

A lekérdezés logikája:

  1. a FROM Licencek megadja a táblát,
  2. a WHERE Aktiv = 1 kiszűri az aktív licenceket,
  3. a GROUP BY Tipus típusonként csoportosít,
  4. a COUNT(*) megszámolja a csoportok elemeit,
  5. az AS AktivLicencekSzama elnevezi a darabszám oszlopát,
  6. az ORDER BY Tipus rendezi az eredményt típus szerint.

Ez azért fontos, mert a feladat nem az összes licencet kéri típusonként, hanem csak az aktív licenceket.

Ez a lekérdezés teljesíti a 6. feladatrészt.

7. lekérdezés – 2026. január 1. előtt ellenőrzött licencek lekérdezése​

SELECT 
    *
FROM Licencek
WHERE UtolsoEllenorzes < '2026-01-01'
ORDER BY UtolsoEllenorzes ASC;

Ez a lekérdezés azokat a licenceket jeleníti meg, amelyek utolsó ellenőrzése 2026. január 1. előtt történt.

Dátum szerinti feltétel​

WHERE UtolsoEllenorzes < '2026-01-01'

Az UtolsoEllenorzes mező dátum típusú adat.

A feltétel azt jelenti, hogy csak azok a sorok jelenjenek meg, ahol az utolsó ellenőrzés dátuma korábbi, mint:

2026-01-01

Mivel a feltételben kisebb mint jel szerepel, a 2026-01-01 dátum már nem kerül bele az eredménybe. Csak az annál korábbi dátumok jelennek meg.

Az ORDER BY szerepe​

ORDER BY UtolsoEllenorzes ASC

Az ORDER BY az eredmény rendezésére szolgál.

Ebben az esetben az UtolsoEllenorzes mező alapján rendezzük az eredményt.

Az ASC szerepe​

ASC

Az ASC növekvő sorrendet jelent.

Dátumok esetében ez azt jelenti, hogy a legkorábbi dátum jelenik meg elöl, majd utána következnek az egyre későbbi dátumok.

Például:

2024-10-21
2024-12-18
2025-08-16
2025-09-23

Ez a lekérdezés teljesíti a 7. feladatrészt.
